# API & Technical Contract — Transivium

Version 0.1 | All five routes implemented through TRN-09. Simulation supports all five machine kinds through TRN-13; four machine acceptor conversions and regex export are available. Independently verified DFA-to-regex export is now implemented at TRN-11; transducer operations follow the backlog. Contract below is the implementation target.

Base: `/api/v1` | JSON UTF-8 | Stateless local server | No auth in proposed MVP. All POST requests use `Content-Type: application/json`. Machine and result schemas defined in 03_DATA_MODEL.md. Examples omit no required fields unless explicitly marked as a field reference. Validate complete request on server; UI hints are not authoritative.

## 1. Routes
| Method / path | Purpose | Request | Success 200 |
|---|---|---|---|
| GET `/health` | Local readiness | none | `{"status":"ok","apiVersion":"v1"}` |
| POST `/validate` | Validate machine | `{"machine": Machine}` | `{valid:true,issues:[]}` or `{valid:false,issues:[Issue]}` for semantic invalidity |
| POST `/simulate` | Run complete input | `{"machine": Machine,"input": string[]}` | SimulationResult (data model) |
| POST `/convert` | Convert/minimize/export | `{"machine": Machine,"operation": Operation}` | ConversionResult (data model) |
| POST `/equivalence` | Exact acceptor comparison | `{"left": Machine,"right": Machine}` | EquivalenceResult (data model) |

`Machine`, `Operation`, `Issue` above are schema references, not literal JSON values. No save/load endpoints because persistence is not in MVP; downloads are generated by client from verified response. API has no public regex-to-DFA endpoint; internal reconstruction is mandatory for export verification.

## 2. POST /validate
Checks structural machine schema and formal invariants. Unknown kind or wrong JSON types produce 422; schema-valid but semantically invalid machine returns 200 with issues. Malformed JSON returns 400. Incomplete UI-only draft must be corrected or converted to schema-shaped data before sending.

Example request:
```json
{"machine":{"kind":"dfa","alphabet":["0"],"states":[{"id":"q0"}],"startState":"q0","finalStates":[],"transitions":[]}}
```
Response:
```json
{"valid":false,"issues":[{"code":"MISSING_TRANSITION","path":"machine.transitions","message":"Missing transition from q0 on 0"}]}
```
Issue fields: `code`, `path`, `message` (strings). Stable machine issue codes: `DUPLICATE_STATE`, `INVALID_ALPHABET`, `UNKNOWN_STATE`, `MISSING_TRANSITION`, `NONDETERMINISTIC_TRANSITION`, `DUPLICATE_TRANSITION`, `INVALID_SYMBOL`, `INVALID_EPSILON`, `INVALID_OUTPUT`, `INVALID_FINAL_STATE`, `INVALID_START_STATE`. Schema shape errors may use `SCHEMA_ERROR`.

## 3. POST /simulate
Request:
```json
{"machine":{"kind":"dfa","alphabet":["0"],"states":[{"id":"q0"}],"startState":"q0","finalStates":["q0"],"transitions":[{"from":"q0","symbol":"0","to":"q0"}]},"input":["0"]}
```
Response:
```json
{"steps":[{"index":0,"symbol":null,"activeStates":["q0"],"movedStates":null,"traversed":[],"epsilonTraversed":[],"outputPrefix":null},{"index":1,"symbol":"0","activeStates":["q0"],"movedStates":null,"traversed":[{"from":"q0","symbol":"0","to":"q0"}],"epsilonTraversed":[],"outputPrefix":null}],"accepted":true,"output":null,"normalizedOutput":null,"initialOutput":null}
```
For Mealy, output and normalizedOutput equal; Moore output includes initial output while normalizedOutput excludes it. Transducer accepted is null. Empty input generates one initial step. NFA dead configuration does not abort; remaining steps have empty active states. Invalid input token yields 422, not `accepted:false`.

## 4. POST /convert
Operation and allowed source:
| Operation | Source | Result |
|---|---|---|
| `enfa_to_nfa` | enfa | nfa |
| `nfa_to_dfa` | nfa | complete dfa |
| `enfa_to_dfa` | enfa | complete dfa |
| `minimize_dfa` | dfa | minimal complete dfa |
| `mealy_to_moore` | mealy | moore |
| `moore_to_mealy` | moore | mealy |
| `dfa_to_regex` | dfa | verified RegexArtifact |

Example regex request:
```json
{"operation":"dfa_to_regex","machine":{"kind":"dfa","alphabet":["0"],"states":[{"id":"q0"}],"startState":"q0","finalStates":["q0"],"transitions":[{"from":"q0","symbol":"0","to":"q0"}]}}
```
Illustrative success (actual derivation may contain additional steps):
```json
{"operation":"dfa_to_regex","machine":null,"steps":[{"index":0,"phase":"eliminate","description":"Eliminate q0","details":{"state":"q0","updates":[{"from":"@start","to":"@final","before":"∅","after":"0*"}]}}],"verification":{"equivalent":true,"mode":"language","method":"product_bfs"},"regexArtifact":{"schemaVersion":1,"syntax":"formal-v1","regex":"0*","alphabet":["0"],"canonicalDfa":{"kind":"dfa","alphabet":["0"],"states":[{"id":"q0"}],"startState":"q0","finalStates":["q0"],"transitions":[{"from":"q0","symbol":"0","to":"q0"}]}}}
```
GNFA synthetic IDs are internal reserved identifiers (`@start`, `@final`), never formal state IDs. For machine conversions `machine` is the generated valid Machine, `regexArtifact:null`; verification mode `language` for acceptor and `normalized_output` for transducer. Verification failure is a typed error, not a 200 conversion.

### DerivationStep details by phase
| Phase | Details (required keys) |
|---|---|
| `closure` | `state: string`, `closure: string[]` |
| `epsilon_removal` | `state: string`, `symbol: string`, `targets: string[]` |
| `subset` | `state: string`, `members: string[]`, `edges: [{symbol,to}]` |
| `reachable` | `states: string[]` |
| `partition` | `blocks: string[][]` |
| `split` | `sourceState: string`, `output: string`, `newState: string` |
| `initial` | `state: string`, `output: string` |
| `relabel` | `from: string`, `to: string`, `symbol: string`, `output: string` |
| `gnfa_init` | `states: string[]`, `edges: [{from,to,regex}]` (nonempty labels only) |
| `eliminate` | `state: string`, `updates: [{from,to,before,after}]` (changed labels only) |
| `verify` | `mode: string`, `equivalent: true` |

Trace order deterministic; phase sequences depend on operation. Include meaningful intermediate steps for actual work; zero-work edge cases still provide initial/final or verification steps. If trace budget exceeded, fail with limit error rather than silently claiming complete trace.

## 5. POST /equivalence
Request fields `left`, `right`: acceptor Machine only, identical alphabet sets (ordering may differ). Convert to complete DFAs if needed; BFS of product finds first differing final status. Returns 200 for both equivalent and non-equivalent valid inputs.
```json
{"equivalent":false,"counterexample":[],"leftAccepts":true,"rightAccepts":false,"visitedPairs":1}
```
This example describes a start-state mismatch. When equivalent, `counterexample`, `leftAccepts` and `rightAccepts` are null. Empty witness array is not null. A witness is shortest by symbol count, tie-broken sorted alphabet.

## 6. Error contract
```json
{"error":{"code":"INVALID_MACHINE","message":"Machine violates DFA requirements","issues":[{"code":"MISSING_TRANSITION","path":"machine.transitions","message":"Missing transition from q0 on 0"}],"requestId":"example-request-id"}}
```
`issues` array always present (may be empty); requestId generated by server. All error paths including framework validation use this envelope.

| Status | Code | Meaning |
|---|---|---|
| 400 | `MALFORMED_JSON` | Invalid JSON syntax |
| 413 | `PAYLOAD_TOO_LARGE` | Body exceeds cap |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | POST is not JSON |
| 422 | `SCHEMA_ERROR`, `INVALID_MACHINE`, `INVALID_INPUT`, `INVALID_OPERATION`, `ALPHABET_MISMATCH` | Correct input then retry |
| 422 | `LIMIT_EXCEEDED` | State/transition/work/trace/response cap exceeded; reduce size |
| 503 | `DEADLINE_EXCEEDED` | Computation budget expired; reduce size or retry |
| 500 | `VERIFICATION_FAILED`, `INTERNAL_ERROR` | No certified result; report request ID; preserve draft |

Framework routes may also return 404/405 using same envelope (`NOT_FOUND`, `METHOD_NOT_ALLOWED`). No client access to exception internals. Network failures have no HTTP envelope; frontend shows connection/retry message.

## 7. Limits / determinism
256 states, 16 input/output symbols, 16,384 transitions, 512 tokens, 512 KiB request, 64 KiB UTF-8 regex, 50,000 AST work allocations, parser nesting 128, 65,536 product pairs, 2,000 derivation steps, 2 MiB response, 5 s cooperative deadline. Intermediate machines obey state/transition limits; budget guards apply before expansion. All limits proposed and tested before release. Sort symbols ASCII and IDs consistently for predictable traces; canonically number minimized DFAs by BFS. Do not silently discard output, approximate equivalence or mark failed export verified.
